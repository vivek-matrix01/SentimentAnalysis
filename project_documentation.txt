1.  PROJECT OVERVIEW
================================================================================

  Project Name  : SentimentAnalysis

  Description   : A full-stack web application that performs Natural Language
                  Processing (NLP) based sentiment analysis on textual data.
                  The application supports two modes of operation:

                    a) Single Text Analysis
                       A user types or pastes any piece of text (e.g., a product
                       review, tweet, or comment) and the system instantly returns
                       the emotional polarity classified as Positive, Neutral, or
                       Negative.

                    b) Batch CSV Analysis
                       A user uploads a CSV file containing multiple rows of text
                       data. The system processes each row through the AI model
                       and returns a full analytics dashboard with charts and a
                       detailed data table.

  Core Purpose  : To provide an accessible, web-based interface for running
                  state-of-the-art AI sentiment models without any need for the
                  end user to know programming or machine learning.

  Primary Users : Data analysts, product teams, researchers, or any individual
                  who wants to understand the emotional tone behind text data.

  Naming Note   : The repository folder is named "Dictionary Application" but
                  the actual project name is "SentimentAnalysis". The folder
                  name appears to be a legacy or placeholder naming artifact.

2.  HIGH-LEVEL ARCHITECTURE
================================================================================

  The project follows a classic client-server (two-tier) architecture with a
  clear separation of concerns between the frontend and backend layers.

  ┌──────────────────────────────────────────────────────────┐
  │                      USER'S BROWSER                      │
  │                                                          │
  │   React SPA  (Single Page Application)                   │
  │   ┌────────────────────────────────────────────────┐     │
  │   │  Single Text Input   |   CSV File Upload       │     │
  │   │  Results Display     |   Dashboard & Charts    │     │
  │   └─────────────────────┬──────────────────────────┘     │
  └─────────────────────────┼────────────────────────────────┘
                            │  HTTP  (REST API calls)
                            │  POST /predict  ->  JSON body
                            │  POST /upload   ->  multipart/form-data
                            v
  ┌──────────────────────────────────────────────────────────┐
  │                  PYTHON FLASK BACKEND                    │
  │                  http://localhost:5000                   │
  │                                                          │
  │   app.py  (Flask Web Server + Route Definitions)         │
  │       |                                                  │
  │       └──>  model/sentiment.py  (AI Analysis Engine)    │
  │                   |                                      │
  │                   |──>  VADER   (Rule-based NLP)         │
  │                   └──>  RoBERTa (Deep Learning Model)    │
  └──────────────────────────────────────────────────────────┘

  Communication : The frontend talks to the backend exclusively over HTTP using
                  the browser Fetch API. There is no WebSocket, no shared
                  database, and no server-side rendering. Both sides run as
                  independent processes on the same machine (localhost).

  CORS          : Cross-Origin Resource Sharing is enabled on the backend using
                  flask-cors so the browser (port 3000) can safely call the
                  server (port 5000) without being blocked by browser policy.

── 5.2   MODEL LAYER:  model/sentiment.py ─────────────────────────────────────

  File Path : backend/model/sentiment.py
  Lines     : 37
  Role      : The AI engine. Loads two sentiment models at module startup and
              exposes one public function:  analyze(text) -> dict

  Module-Level Initialization  (runs once on import):
  ─────────────────────────────────────────────────────

    VADER:
      sia = SentimentIntensityAnalyzer()
      Loads the VADER lexicon from the NLTK data directory.
      Very fast — initializes in milliseconds.

    RoBERTa:
      MODEL     = "cardiffnlp/twitter-roberta-base-sentiment"
      tokenizer = AutoTokenizer.from_pretrained(MODEL)
      model     = AutoModelForSequenceClassification.from_pretrained(MODEL)

      - Downloads model weights from Hugging Face Hub on first run (~500 MB).
        Cached locally in ~/.cache/huggingface/ on all subsequent runs.
      - RoBERTa-base fine-tuned on ~58 million tweets for 3-class sentiment.
      - Initialization runs once at server startup, keeping per-request
        inference fast (no model reload per request).

  Functions:
  ──────────

    vader_sentiment(text: str) -> dict
      Uses NLTK's SentimentIntensityAnalyzer.
      Returns: { "neg": float, "neu": float, "pos": float, "compound": float }
      The "compound" score is a normalized weighted composite in [-1.0, +1.0].

    roberta_sentiment(text: str) -> dict
      Step 1: Tokenizes text using AutoTokenizer (BPE encoding).
              Produces input_ids and attention_mask as PyTorch tensors.
      Step 2: Passes tensors through the RoBERTa model (forward pass).
      Step 3: Extracts raw logits from model output.
      Step 4: Calls .detach().numpy() to convert tensor to a NumPy array.
      Step 5: Applies softmax to produce a probability distribution (0.0–1.0).
      Returns: { "roberta_neg": float, "roberta_neu": float, "roberta_pos": float }
      All three values always sum to exactly 1.0.

    analyze(text: str) -> dict   [THE PUBLIC API]
      Orchestrates both models and merges their outputs.
      Returns: {
        "vader":   { "neg": f, "neu": f, "pos": f, "compound": f },
        "roberta": { "roberta_neg": f, "roberta_neu": f, "roberta_pos": f }
      }

── 5.5   PYTHON DEPENDENCY MANAGEMENT ─────────────────────────────────────────

  Tool:  uv  (https://github.com/astral-sh/uv)
    A modern, Rust-based Python package manager significantly faster than pip.
    Manages virtual environments, resolves dependencies, and generates lockfiles.

  pyproject.toml:
    The authoritative dependency specification. Lists direct dependencies with
    minimum version constraints (>=). Requires Python >= 3.14.

  req.txt:
    A simplified list of the same dependencies without version pins.
    Used by setup.sh:  uv add -r req.txt
    Functionally equivalent to a traditional requirements.txt file.

  uv.lock:
    Auto-generated by uv. Contains exact versions of ALL packages including
    transitive/indirect dependencies. Ensures reproducible installs across
    machines. Should be committed to version control.

  .venv/:
    The virtual environment created by uv inside the backend folder.
    All Python dependencies are installed here, isolated from system Python.

  setup.sh  (first-time setup — two commands):
    1.  uv add -r req.txt
        Installs all packages into .venv.
    2.  python -m nltk.downloader punkt vader_lexicon
                averaged_perceptron_tagger maxent_ne_chunker words
        Downloads required NLTK corpora and models to disk.

── 6.5   DATA FLOW  (Frontend <-> Backend) ────────────────────────────────────

  Single Text Flow:
    1.  User types in textarea  ->  text state updates on every keystroke
    2.  User clicks "Analyze Sentiment"
    3.  isAnalyzing -> true
    4.  fetch("http://localhost:5000/predict", { method: "POST", body: JSON })
    5.  Awaits response
    6.  setResult(data)  ->  triggers re-render
    7.  isAnalyzing -> false
    8.  Results block appears below the textarea

  Batch CSV Flow:
    1.  User selects a .csv file  ->  file state is set
    2.  User clicks "Process CSV"
    3.  isUploading -> true
    4.  FormData object created, file appended
    5.  fetch("http://localhost:5000/upload", { method: "POST", body: formData })
    6.  Awaits response
    7.  setBatchData(data.results)  ->  triggers re-render
    8.  setUploadStatus("Upload successful")
    9.  isUploading -> false
    10. Dashboard section becomes visible

8.  SENTIMENT ANALYSIS ENGINES
================================================================================


── 8.1   VADER  (Valence Aware Dictionary and sEntiment Reasoner) ──────────────

  Source    : NLTK library  (nltk.sentiment.SentimentIntensityAnalyzer)
  Type      : Rule-based / Lexicon-based — NOT machine learning
  Dataset   : Hand-curated dictionary of ~7,500 lexical features with
              associated sentiment valence scores
  Speed     : Extremely fast — milliseconds per text, no GPU required
  Best For  : Social media text, short sentences, informal language

  How It Works:
    - Each word in the text is looked up in the VADER lexicon
    - Words are scored for positive or negative sentiment intensity
    - Additional heuristics adjust scores for:
        Capitalization   (e.g., "GREAT" scores higher than "great")
        Punctuation      (e.g., "!!!" amplifies score intensity)
        Negation         (e.g., "not great" inverts the word's score)
        Booster words    (e.g., "very", "extremely" amplify the next word)
    - A compound score [-1, 1] is computed as a normalized weighted composite
    - neg + neu + pos always sum to 1.0

  Output Example for "This product is amazing!":
    { "neg": 0.0, "neu": 0.412, "pos": 0.588, "compound": 0.6249 }


── 8.2   RoBERTa  (twitter-roberta-base-sentiment) ────────────────────────────

  Source    : Hugging Face Transformers
              Model ID: "cardiffnlp/twitter-roberta-base-sentiment"
  Type      : Deep Learning — Transformer-based language model
  Base      : RoBERTa-base (125M parameters), fine-tuned on ~58M tweets
  Provider  : Cardiff NLP  (Cardiff University, UK)
  Labels    : 3 classes — Negative (0), Neutral (1), Positive (2)
  Speed     : Slower than VADER — typically 0.5 to 2 seconds per text on CPU
  Best For  : Context-aware understanding, nuanced language, sarcasm detection

  How It Works:

    Step 1 — Tokenization:
      Text is tokenized using Byte-Pair Encoding (BPE).
      Special [CLS] and [SEP] tokens are added automatically.
      Output: input_ids and attention_mask as PyTorch tensors.

    Step 2 — Forward Pass:
      Tensors pass through 12 transformer layers.
      Each layer applies self-attention across all token pairs simultaneously.
      The [CLS] token's final output represents the whole sentence's meaning.

    Step 3 — Classification Head:
      A linear layer maps the [CLS] vector to 3 raw logit scores.

    Step 4 — Softmax:
      scipy.special.softmax converts logits to a probability distribution.
      Ensures all three output values sum to exactly 1.0.

  Output Example for "This product is amazing!":
    { "roberta_neg": 0.021, "roberta_neu": 0.056, "roberta_pos": 0.923 }

  Note: The model runs in inference mode. torch.no_grad() is not explicitly
        called, but .detach() is used before .numpy() to disconnect the tensor
        from the computation graph, which is functionally equivalent.


── 8.3   COMPARISON OF BOTH ENGINES ───────────────────────────────────────────

  ┌─────────────────────┬──────────────────────────┬──────────────────────────┐
  │  Feature            │  VADER                   │  RoBERTa                 │
  ├─────────────────────┼──────────────────────────┼──────────────────────────┤
  │  Method             │  Rule-based lexicon       │  Deep neural network     │
  │  Training data      │  Hand-crafted dictionary  │  58 million tweets       │
  │  Context awareness  │  Limited  (word-level)    │  High  (full sentence)   │
  │  Speed              │  < 1 ms                  │  0.5 – 2 s  (on CPU)    │
  │  GPU required       │  No                      │  No  (faster with GPU)   │
  │  Model size         │  Tiny  (~100 KB)          │  Large  (~500 MB)        │
  │  Best for           │  Informal, social text    │  All text, nuanced lang  │
  │  Handles sarcasm    │  Poorly                  │  Better  (not perfect)   │
  │  Compound score     │  Yes  (range -1 to +1)   │  No  (probabilities only)│
  │  Zero-shot ability  │  Yes  (any text domain)   │  Tuned for tweet style   │
  └─────────────────────┴──────────────────────────┴──────────────────────────┘

  Current Behavior:
    Both models run on every request, for both /predict and /upload endpoints.
    Only RoBERTa results are shown in the frontend UI.
    VADER results are returned in the API payload but currently unused in UI.

10.  REQUEST-RESPONSE LIFECYCLE  (End-to-End)
================================================================================

  Example: User types "This is a great product!" and clicks Analyze.

  Step 1  — User Input
    React detects onChange on the textarea.
    setText("This is a great product!") is called.
    The button becomes enabled because text is not empty.

  Step 2  — Button Click
    analyze() function is invoked.
    isAnalyzing -> true  (button shows "Analyzing..." and is disabled).

  Step 3  — HTTP Request Sent
    Browser sends:  POST  http://localhost:5000/predict
    Headers:  { Content-Type: application/json }
    Body:     { "text": "This is a great product!" }

  Step 4  — Flask Receives Request
    The /predict route handler fires.
    data = request.json.get("text", "")  extracts the text string.
    analyze(data) is called from model/sentiment.py.

  Step 5  — VADER Analysis Runs
    sia.polarity_scores("This is a great product!") executes.
    Returns: { neg: 0.0, neu: 0.423, pos: 0.577, compound: 0.6588 }

  Step 6  — RoBERTa Analysis Runs
    Tokenizer converts the text to input tensors.
    Model performs a forward pass through 12 transformer layers.
    Logits are extracted and softmax is applied.
    Returns: { roberta_neg: 0.02, roberta_neu: 0.08, roberta_pos: 0.90 }

  Step 7  — Flask Sends Response
    Both results are merged into one dict and returned as JSON.
    HTTP 200 OK response is sent back to the browser.

  Step 8  — Frontend Processes Response
    The fetch() promise resolves with the response data.
    setResult(data) updates component state and triggers re-render.
    isAnalyzing -> false.
    React re-renders and the results block appears with the three values.

  Total Round-Trip Time:
    Typically 0.5 to 3 seconds on CPU, dominated by RoBERTa inference.

11.  DESIGN PHILOSOPHY & UI/UX DECISIONS
================================================================================

  1.  GLASSMORPHISM
      Panels use semi-transparent white backgrounds with backdrop-filter: blur().
      This creates a frosted glass effect over the gradient background.
      A popular 2024-era design trend used in SaaS and AI-powered web tools.

  2.  GRADIENT AESTHETICS
      The page background uses two radial gradients (blue and purple) to create
      a soft ambient glow. The header title uses a CSS linear gradient as a
      text fill via -webkit-background-clip. These choices align the UI
      visually with modern AI product design language.

  3.  PROGRESSIVE DISCLOSURE
      The dashboard section is hidden until batchData.length > 0.
      This keeps the interface minimal and focused, revealing complexity
      only after user action produces meaningful data.

  4.  STAGGERED ANIMATIONS
      Each section animates in with an increasing delay (0ms, 100ms, 200ms,
      300ms), creating a natural sequential reveal that guides the user's
      attention down the page in a controlled, comfortable way.

  5.  SEMANTIC COLOR CODING
      Green = Positive, Amber = Neutral, Red = Negative is applied consistently
      across stat cards, chart bars, data table values, and score badges.
      Users can understand results at a glance without reading every label.

  6.  CUSTOM FILE INPUT
      The native browser <input type="file"> element is hidden with opacity:0
      and overlaid with a custom-styled display div. This is the standard
      technique for achieving a consistent cross-browser look while keeping
      the native file dialog behavior intact.

  7.  RESPONSIVE GRID
      The two-panel layout uses CSS Grid with auto-fit and minmax(300px, 1fr).
      This causes panels to flow naturally from two columns to one column
      on narrower screens, with no breakpoint media queries needed.

  8.  DUAL MODEL ARCHITECTURE
      Returning both VADER and RoBERTa results from every API call keeps the
      backend flexible. Future UI features like model comparison, discrepancy
      highlighting, or ensemble scoring can be added without any backend changes.

12.  KNOWN LIMITATIONS
================================================================================

  1.  NO AUTHENTICATION
      The API has no auth layer. Anyone on the same network with access to
      port 5000 can call all endpoints without restriction.

  2.  HARDCODED ROW LIMIT
      The /upload endpoint silently caps processing at 50 rows via df.head(50).
      Larger datasets are truncated with no warning displayed to the user.

  3.  TEXT LENGTH NOT VALIDATED
      RoBERTa has a maximum token limit of 512 tokens. Texts longer than
      approximately 400 words will be silently truncated by the tokenizer,
      which may reduce accuracy without any indication to the user.

  4.  NO READINESS ENDPOINT
      When Flask starts, loading RoBERTa takes 10–30 seconds (cold start).
      Requests that arrive during this window may time out or return errors.
      There is no /health or /ready endpoint to check server readiness.

  5.  VADER OUTPUT NOT DISPLAYED
      VADER results are computed and returned by the API on every request but
      are not rendered anywhere in the frontend. Half the model's work is
      discarded after each call.

  6.  FRONTEND ERROR HANDLING IS SILENT
      Network errors and HTTP failures are only logged to the browser console
      via console.error(). No visible error message is shown to the user when
      the backend is unavailable for single-text analysis.

  7.  NO DATA PERSISTENCE
      Results live only in React component state. Refreshing the page wipes
      everything. There is no database, localStorage, or session storage.

  8.  CPU-ONLY INFERENCE
      The code does not move the model or tensors to CUDA. All inference runs
      on CPU, which is significantly slower than GPU-accelerated environments.

  9.  CORS IS FULLY OPEN
      CORS(app) with no restrictions is appropriate for local development but
      would be a security concern in any production deployment.

  10. MISLEADING FOLDER NAME
      The project lives inside a folder named "Dictionary Application" even
      though there is no dictionary functionality. This may cause confusion
      when navigating the filesystem.

14.  GLOSSARY
================================================================================

  API           Application Programming Interface — a contract defining how
                software components communicate (here, via HTTP endpoints).

  CORS          Cross-Origin Resource Sharing — a browser security policy that
                restricts web pages from calling a different domain unless the
                server explicitly allows it via response headers.

  CSP           Content Security Policy — an additional browser-level security
                layer. Not implemented in this project.

  CSV           Comma-Separated Values — a plain-text tabular data format where
                columns are separated by commas and rows by newlines.

  HMR           Hot Module Replacement — a development feature where saved code
                changes are pushed to the browser without a full page refresh.

  Hugging Face  A company and open-source platform hosting thousands of
                pre-trained AI models, datasets, and interactive demos.

  Logits        Raw, un-normalized output scores from a neural network's final
                linear layer, before any activation function is applied.

  NLP           Natural Language Processing — the field of AI focused on
                teaching machines to understand and generate human language.

  RoBERTa       Robustly Optimized BERT Pretraining Approach — a transformer
                language model by Facebook AI Research, an improved version
                of Google's BERT.

  SPA           Single Page Application — a web app that loads one HTML shell
                and dynamically updates its content via JavaScript.

  Softmax       A mathematical function that converts a vector of real numbers
                (logits) into a probability distribution that sums to 1.0.

  Tokenizer     Breaks input text into smaller units (tokens) for model input.
                RoBERTa uses Byte-Pair Encoding (BPE) as its tokenization method.

  Transformer   A deep learning architecture that uses self-attention to model
                the relationship between every word in a sentence simultaneously.

  VADER         Valence Aware Dictionary and sEntiment Reasoner — a rule-based
                NLP tool for sentiment analysis, included in the NLTK library.

  WSGI          Web Server Gateway Interface — the standard Python protocol
                connecting web servers (Gunicorn) to web apps (Flask).

  uv            A Rust-based Python package manager by Astral that replaces
                pip and venv. Extremely fast dependency resolution.

  Virtual Env   An isolated Python environment (.venv) containing only the
                packages needed for this project, separate from system Python.

  Web Vitals    A set of user experience metrics defined by Google:
                LCP (load speed), FID (interactivity), CLS (visual stability).
